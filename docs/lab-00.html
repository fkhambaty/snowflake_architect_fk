Bootstrap — understand each chunk, then run

You can run chunks one-by-one (best for learning) or the full script at the bottom.

Chunk A — become admin + create the cheap warehouse

Understand this before you copy

SQLPlain English
USE ROLE ACCOUNTADMINWear the bootstrap badge (only for setup)
CREATE WAREHOUSE … XSMALLCreate a tiny SQL engine so labs cost almost nothing
AUTO_SUSPEND = 60Turn the engine off after 60s idle → saves credits
AUTO_RESUME = TRUEWake it automatically when you run SQL
IF NOT EXISTSSafe to re-run; won’t explode if it already exists
Interview: “I right-size warehouses and auto-suspend so demos don’t burn money.”
SQL · warehouse
USE ROLE ACCOUNTADMIN;

CREATE WAREHOUSE IF NOT EXISTS WH_ARCH_XS
  WAREHOUSE_SIZE = 'XSMALL'
  AUTO_SUSPEND = 60
  AUTO_RESUME = TRUE
  INITIALLY_SUSPENDED = TRUE
  COMMENT = 'Interview prep lab warehouse';

Chunk B — create lab admin role + give it powers

Understand this before you copy

SQLPlain English
CREATE ROLE ROLE_ARCH_LAB_ADMINInvent a badge that will own the lab playground
GRANT CREATE ROLE ON ACCOUNT …Allow creating FR_*/AR_* roles (Lab 01)
APPLY MASKING / ROW ACCESS POLICYAttach governance policies (Lab 03)
EXECUTE TASKRun stream→task pipelines (Lab 05)
CREATE SHAREProvider-side data share (Lab 10)
USAGE / OPERATE … WITH GRANT OPTIONUse warehouse and pass it to other roles
GRANT OWNERSHIP ON DATABASE …Lab admin owns the playground
Missing these account grants is what caused the Lab 01 CREATE ROLE error — and will break Labs 03/05/10 too.
SQL · role + database + full-course grants
CREATE ROLE IF NOT EXISTS ROLE_ARCH_LAB_ADMIN
  COMMENT = 'Owns interview prep lab objects';

GRANT CREATE ROLE ON ACCOUNT TO ROLE ROLE_ARCH_LAB_ADMIN;
GRANT APPLY MASKING POLICY ON ACCOUNT TO ROLE ROLE_ARCH_LAB_ADMIN;
GRANT APPLY ROW ACCESS POLICY ON ACCOUNT TO ROLE ROLE_ARCH_LAB_ADMIN;
GRANT EXECUTE TASK ON ACCOUNT TO ROLE ROLE_ARCH_LAB_ADMIN;
GRANT CREATE SHARE ON ACCOUNT TO ROLE ROLE_ARCH_LAB_ADMIN;

GRANT USAGE ON WAREHOUSE WH_ARCH_XS TO ROLE ROLE_ARCH_LAB_ADMIN WITH GRANT OPTION;
GRANT OPERATE ON WAREHOUSE WH_ARCH_XS TO ROLE ROLE_ARCH_LAB_ADMIN WITH GRANT OPTION;

CREATE DATABASE IF NOT EXISTS ARCH_INTERVIEW
  COMMENT = 'Snowflake Architect interview prep';

GRANT OWNERSHIP ON DATABASE ARCH_INTERVIEW TO ROLE ROLE_ARCH_LAB_ADMIN COPY CURRENT GRANTS;

SET uname = (SELECT CURRENT_USER());
GRANT ROLE ROLE_ARCH_LAB_ADMIN TO USER IDENTIFIER($uname);

Chunk C — smoke test + schemas

Understand this before you copy

We switch into lab admin and try creating a throwaway role. If that fails, stop — Lab 01 will fail too.

Then we create six schemas (subfolders): RAW (landing), CURATED (clean), SECURE (sensitive), UTILS (helpers), MART (gold reports), STAGE_DATA (file landing).

Snowflake also shows PUBLIC and INFORMATION_SCHEMA automatically — that is normal, not a mistake.

Naming layers like this is how you talk about medallion / zone architecture in interviews.
SQL · smoke test + schemas
USE ROLE ROLE_ARCH_LAB_ADMIN;
CREATE ROLE IF NOT EXISTS ROLE_ARCH_SMOKE_TMP COMMENT = 'temp smoke test - safe to drop';
DROP ROLE IF EXISTS ROLE_ARCH_SMOKE_TMP;

USE WAREHOUSE WH_ARCH_XS;
USE DATABASE ARCH_INTERVIEW;

CREATE SCHEMA IF NOT EXISTS RAW;
CREATE SCHEMA IF NOT EXISTS CURATED;
CREATE SCHEMA IF NOT EXISTS SECURE;
CREATE SCHEMA IF NOT EXISTS UTILS;
CREATE SCHEMA IF NOT EXISTS MART;
CREATE SCHEMA IF NOT EXISTS STAGE_DATA;

SELECT CURRENT_ROLE() AS role, CURRENT_WAREHOUSE() AS wh, CURRENT_DATABASE() AS db;
SHOW SCHEMAS IN DATABASE ARCH_INTERVIEW;
SELECT 'Lab 00 bootstrap OK — CREATE ROLE smoke test passed' AS status;
Success message You must see Lab 00 bootstrap OK — CREATE ROLE smoke test passed.

Load sample customers (needed for Lab 01)

Tiny fake table with emails and SSN last-4 so we can practice hiding PII next.

SQL · sample customers 
USE ROLE ROLE_ARCH_LAB_ADMIN;
USE WAREHOUSE WH_ARCH_XS;
USE DATABASE ARCH_INTERVIEW;
USE SCHEMA RAW;

CREATE OR REPLACE TABLE CUSTOMERS (
  CUSTOMER_ID   NUMBER,
  FULL_NAME     STRING,
  EMAIL         STRING,
  PHONE         STRING,
  COUNTRY       STRING,
  SSN_LAST4     STRING,
  CREATED_AT    TIMESTAMP_NTZ DEFAULT CURRENT_TIMESTAMP()
);

INSERT INTO CUSTOMERS (CUSTOMER_ID, FULL_NAME, EMAIL, PHONE, COUNTRY, SSN_LAST4) VALUES
  (1, 'Asha Patel',  'asha.patel@example.com',  '+1-555-0101', 'US', '1234'),
  (2, 'Ben Okonkwo', 'ben.okonkwo@example.com', '+1-555-0102', 'US', '5678'),
  (3, 'Chen Wei',    'chen.wei@example.com',    '+1-555-0103', 'CA', '9012'),
  (4, 'Diana Rossi', 'diana.rossi@example.com', '+1-555-0104', 'US', '3456'),
  (5, 'Evan Ng',     'evan.ng@example.com',     '+1-555-0105', 'UK', '7890');

SELECT * FROM CUSTOMERS ORDER BY CUSTOMER_ID;
