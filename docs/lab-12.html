Lab 12 · Sunday · You are Elena · Alex’s broken metric

Silent dbt changes broke the board deck

Lab 02 proved incremental merge. Now many developers change models — sources, contracts, Slim CI so PRs don’t rebuild the world.

Business problem A column rename in the txn mart shipped without notice. Alex’s Looker tile went blank before the board meeting. Marcus: “Govern the published marts.”
Solution you will design Declare landing.txn_events in sources, enforce contract on fct_orders_incremental, Slim CI with state:modified+ and defer.

Jordan owns git; Elena owns what may break Alex — contracts on published marts, not every staging view.

1

Sources boundary — LANDING.TXN_EVENTS

YAML · dbt_project/models/staging/_sources.yml
version: 2

sources:
  - name: landing
    database: MERIDIAN_BANK
    schema: LANDING
    tables:
      - name: txn_events
        description: "Meridian Bank txn events for incremental merge demo"
2

Contract on the published mart

YAML · contract example
version: 2

models:
  - name: fct_orders_incremental
    config:
      contract:
        enforced: true
    columns:
      - name: order_id
        data_type: number
        tests: [unique, not_null]
      - name: customer_id
        data_type: number
      - name: status
        data_type: varchar
      - name: order_total
        data_type: number
      - name: updated_at
        data_type: timestamp_ntz
        tests: [not_null]
3

Slim CI commands (illustration)

Shell
dbt deps
dbt ls --select state:modified+ --resource-type model --state ./prod_artifact/
dbt build --select state:modified+ --defer --state ./prod_artifact/
Elena’s wrap-up (say this out loud)
“Meridian’s mart broke because nobody enforced the published schema. I declared landing.txn_events as a dbt source, enforced a contract on fct_orders_incremental, and described Slim CI so PRs only build state:modified+ with defer to prod manifest. Outcome: Alex’s dashboards get stable columns; Jordan’s team ships faster without full-graph builds every time.”
