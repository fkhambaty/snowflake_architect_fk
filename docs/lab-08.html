2

Confirm BIG_EVENTS from Lab 07

What this does

Lab 07 created ~400k unclustered rows and kept them on purpose. Confirm volume before you cluster.

What you should see

ROW_CNT near 400000. If the table is missing, run the optional rebuild block once.

SQL · verify Lab 07 table
SELECT COUNT(*) AS ROW_CNT, MIN(EVENT_DATE) AS MIN_DT, MAX(EVENT_DATE) AS MAX_DT
FROM BIG_EVENTS;
SQL · optional rebuild (only if you skipped Lab 07)
CREATE OR REPLACE TABLE BIG_EVENTS AS
SELECT
  SEQ4() AS EVENT_ID,
  UNIFORM(1, 5, RANDOM()) AS CLIENT_ID,
  DATEADD('day', -UNIFORM(0, 364, RANDOM()), CURRENT_DATE()) AS EVENT_DATE,
  UNIFORM(1, 100, RANDOM())::NUMBER(12, 2) AS AMOUNT,
  UNIFORM(1, 4, RANDOM()) AS STATUS_CODE
FROM TABLE(GENERATOR(ROWCOUNT => 400000));
✓ ~400k rows — same table Lab 07 profiled
3

Read clustering health (before)

What this does

Asks Snowflake how well rows align on EVENT_DATE before we declare a clustering key.

What you should see

JSON-ish stats — overlap / depth numbers. Interview: “I’d track this after loads; re-cluster if overlap drifts.”

SQL · clustering information
SELECT SYSTEM$CLUSTERING_INFORMATION(
  'SILVER_CURATED.BIG_EVENTS', '(EVENT_DATE)'
);
4

Declare the clustering key

What this does

ALTER TABLE … CLUSTER BY (EVENT_DATE) tells Snowflake to maintain better date locality over time (automatic background work).

SQL · cluster key
ALTER TABLE BIG_EVENTS CLUSTER BY (EVENT_DATE);
✓ Table DDL shows clustering key EVENT_DATE in Snowsight
5

Run Alex’s “last 7 days” aggregate

What this does

Same business filter Risk runs daily — count and sum only recent events.

What you should see

One result row (count + sum). Re-check clustering information after; tie bytes/pruning back to Lab 07 Profile vocabulary.

SQL · filtered aggregate
SELECT COUNT(*), SUM(AMOUNT)
FROM BIG_EVENTS
WHERE EVENT_DATE >= DATEADD('day', -7, CURRENT_DATE());
SQL · clustering information (after)
SELECT SYSTEM$CLUSTERING_INFORMATION(
  'SILVER_CURATED.BIG_EVENTS', '(EVENT_DATE)'
);
SQL · status
SELECT 'Lab 08 clustering demo ready — BIG_EVENTS clustered on EVENT_DATE' AS status;
