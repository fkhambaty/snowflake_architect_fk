Lab 01 · Domain 1.2 · ~40 minutes · Top interview topic

RBAC like an architect

Interviewers love this: “How do you stop analysts from seeing SSN/email while still letting them work?” You will build the answer, then prove it with a failing query.

Stop — did you finish Lab 00? You need database ARCH_INTERVIEW and table RAW.CUSTOMERS with 5 rows. If not, go to Lab 00 first.
Two kinds of roles (remember this sentence)
  • Functional role = who you are at work (Analyst, Engineer, Compliance)
  • Access role = a permission pack (can read curated / can read PII)
People get functional roles. Functional roles get access roles. Access roles get table privileges. Never give humans random table grants one-by-one forever.

2

Build the role graph + safe view

One big script. Copy → paste → Run All. Then breathe.

SQL · Lab 01 RBAC (full script)
USE ROLE ROLE_ARCH_LAB_ADMIN;
USE WAREHOUSE WH_ARCH_XS;
USE DATABASE ARCH_INTERVIEW;

CREATE ROLE IF NOT EXISTS AR_RAW_READ;
CREATE ROLE IF NOT EXISTS AR_CURATED_READ;
CREATE ROLE IF NOT EXISTS AR_PII_READ;

CREATE ROLE IF NOT EXISTS FR_ANALYST;
CREATE ROLE IF NOT EXISTS FR_DATA_ENGINEER;
CREATE ROLE IF NOT EXISTS FR_COMPLIANCE;

GRANT USAGE ON WAREHOUSE WH_ARCH_XS TO ROLE FR_ANALYST;
GRANT USAGE ON WAREHOUSE WH_ARCH_XS TO ROLE FR_DATA_ENGINEER;
GRANT USAGE ON WAREHOUSE WH_ARCH_XS TO ROLE FR_COMPLIANCE;

GRANT USAGE ON DATABASE ARCH_INTERVIEW TO ROLE AR_RAW_READ;
GRANT USAGE ON DATABASE ARCH_INTERVIEW TO ROLE AR_CURATED_READ;
GRANT USAGE ON DATABASE ARCH_INTERVIEW TO ROLE AR_PII_READ;

GRANT USAGE ON SCHEMA RAW TO ROLE AR_RAW_READ;
GRANT USAGE ON SCHEMA CURATED TO ROLE AR_CURATED_READ;
GRANT USAGE ON SCHEMA SECURE TO ROLE AR_PII_READ;
GRANT USAGE ON SCHEMA RAW TO ROLE AR_PII_READ;

GRANT SELECT ON ALL TABLES IN SCHEMA RAW TO ROLE AR_RAW_READ;
GRANT SELECT ON FUTURE TABLES IN SCHEMA RAW TO ROLE AR_RAW_READ;
GRANT SELECT ON ALL TABLES IN SCHEMA CURATED TO ROLE AR_CURATED_READ;
GRANT SELECT ON FUTURE TABLES IN SCHEMA CURATED TO ROLE AR_CURATED_READ;
GRANT SELECT ON ALL TABLES IN SCHEMA RAW TO ROLE AR_PII_READ;
GRANT SELECT ON FUTURE TABLES IN SCHEMA RAW TO ROLE AR_PII_READ;

GRANT ROLE AR_CURATED_READ TO ROLE FR_ANALYST;
GRANT ROLE AR_RAW_READ TO ROLE FR_DATA_ENGINEER;
GRANT ROLE AR_CURATED_READ TO ROLE FR_DATA_ENGINEER;
GRANT ROLE AR_PII_READ TO ROLE FR_COMPLIANCE;
GRANT ROLE AR_CURATED_READ TO ROLE FR_COMPLIANCE;

SET uname = (SELECT CURRENT_USER());
GRANT ROLE FR_ANALYST TO USER IDENTIFIER($uname);
GRANT ROLE FR_DATA_ENGINEER TO USER IDENTIFIER($uname);
GRANT ROLE FR_COMPLIANCE TO USER IDENTIFIER($uname);

USE SCHEMA CURATED;
CREATE OR REPLACE VIEW V_CUSTOMERS_PUBLIC AS
SELECT CUSTOMER_ID, FULL_NAME, COUNTRY, CREATED_AT
FROM RAW.CUSTOMERS;

GRANT SELECT ON VIEW V_CUSTOMERS_PUBLIC TO ROLE AR_CURATED_READ;

SELECT 'RBAC objects created' AS status;
What just happened? Analysts get a view with no email/phone/SSN. Engineers can still read RAW for pipelines. Compliance can read PII. Same person (you) can switch roles to test each path.
3

Become the Analyst — prove PII is blocked

This is the money demo. Change the Role chip first or the test is useless.

Role: FR_ANALYST ▾
WH: WH_ARCH_XS ▾
DB: ARCH_INTERVIEW ▾

Click the Role dropdown (glowing) → pick FR_ANALYST → wait a second.

A) This should WORK

SQL · analyst safe query
USE ROLE FR_ANALYST;
USE WAREHOUSE WH_ARCH_XS;
USE DATABASE ARCH_INTERVIEW;
SELECT * FROM CURATED.V_CUSTOMERS_PUBLIC;
CUSTOMER_IDFULL_NAMECOUNTRY
1Asha PatelUS
2Ben OkonkwoUS
✓ No EMAIL / PHONE / SSN columns. That is the point.

B) This should FAIL (red error = success for the lesson)

SQL · analyst forbidden query
SELECT * FROM RAW.CUSTOMERS;
✗ Insufficient privileges — this is EXACTLY what you want to show in an interview.

Become Engineer, then Compliance

Switch role chip each time.

SQL · engineer can read RAW
USE ROLE FR_DATA_ENGINEER;
SELECT CUSTOMER_ID, EMAIL FROM RAW.CUSTOMERS LIMIT 5;
✓ Engineer path works (pipeline work).
SQL · compliance can read PII
USE ROLE FR_COMPLIANCE;
SELECT CUSTOMER_ID, SSN_LAST4 FROM RAW.CUSTOMERS;
✓ Compliance path works.
5

Inspect grants (architect habit)

Show you can “read the wiring,” not only create it.

SQL · show grants
USE ROLE ROLE_ARCH_LAB_ADMIN;
SHOW GRANTS TO ROLE FR_ANALYST;
SHOW GRANTS TO ROLE AR_CURATED_READ;
SHOW GRANTS OF ROLE AR_CURATED_READ;
60-second interview answer (practice out loud)
“I separate functional roles from access roles. Analysts inherit curated-read only, so they query a view without PII. Engineers get raw for pipelines. Compliance gets PII access. I just proved analyst select on RAW fails. In production I’d add masking policies and future grants so new tables don’t become world-readable.”
