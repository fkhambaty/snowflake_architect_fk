Lab 03 · Security · Understand first, then run

Dynamic Data Masking + Row Access Policies

Rule: read the blue box → copy the small SQL under it. Lab 01 blocked analysts from RAW. Here we let analysts SELECT a curated table — but Snowflake still hides email and filters countries by role.

What you will explain in an interview
  • Masking policy = hide or transform a column value at query time
  • Row access policy = hide entire rows unless the role is entitled
  • Policies sit on CURATED.CUSTOMERS_GOV — not on RAW — so FR_ANALYST can run the demo
Prerequisites Lab 00 (ARCH_INTERVIEW, RAW.CUSTOMERS) and Lab 01 (roles + FR_ANALYST / FR_COMPLIANCE).

Big picture (30 seconds)

RBAC says “can you open this table?” Policies say “given you can open it, what do you actually see?” Same table, same SELECT — different roles → different rows and column values.

Privilege repair (ACCOUNTADMIN — apply policies + tasks later)

Run this if ALTER TABLE … SET MASKING POLICY or row policy attach fails with insufficient privileges.

Understand this before you copy

Attaching masking and row access policies is an account-level power. Lab admin owns the database, but Snowflake still wants explicit APPLY … POLICY grants.

SQL ideaPlain English
GRANT APPLY MASKING POLICY ON ACCOUNT …Allow this role to attach column masks
GRANT APPLY ROW ACCESS POLICY ON ACCOUNT …Allow this role to attach row filters
GRANT EXECUTE TASK ON ACCOUNT …Prep for Lab 05 (manual task runs)
CREATE ROLE … SMOKE_TMP then DROPQuick test that CREATE ROLE still works
Why: Without APPLY grants, policy DDL fails even when you own the table.
Role: ACCOUNTADMIN ▾

2

Create masking policy (hide email for most roles)

Understand this before you copy

A masking policy is a tiny function Snowflake runs when someone reads a column. Compliance and lab admin see the real email; everyone else gets ***@domain.

SQLPlain English
CREATE MASKING POLICY … AS (val STRING) RETURNS STRINGDefine how to transform one string column
CURRENT_ROLE() IN (…)Who sees the real value?
REGEXP_REPLACE(val, '.+@', '***@')Keep domain, hide local part
Interview line: “Masking is role-aware column obfuscation at read time — not encryption at rest.”
SQL · masking policy
USE SCHEMA SECURE;

CREATE OR REPLACE MASKING POLICY MP_EMAIL_MASK AS (val STRING)
  RETURNS STRING ->
  CASE
    WHEN CURRENT_ROLE() IN ('FR_COMPLIANCE', 'ROLE_ARCH_LAB_ADMIN') THEN val
    ELSE REGEXP_REPLACE(val, '.+@', '***@')
  END;
3

Entitlement table + row access policy (country filter)

Understand this before you copy

Row access policies need a rule: “show row only if …”. We store allowed (role, country) pairs in a table and check CURRENT_ROLE() against it.

SQLPlain English
RAP_COUNTRY_ENTITLEMENTLookup: which countries each role may see
ROW ACCESS POLICY … ON (COUNTRY)Filter uses the table’s COUNTRY column
EXISTS (SELECT 1 FROM … WHERE ROLE_NAME = CURRENT_ROLE())Row visible only if role is entitled to that country
Analyst gets US only. Compliance gets US, CA, UK — so you can prove wider row visibility.

Chunk A — entitlement rows

SQL · entitlement table
CREATE OR REPLACE TABLE RAP_COUNTRY_ENTITLEMENT (
  ROLE_NAME STRING,
  COUNTRY   STRING
);

DELETE FROM RAP_COUNTRY_ENTITLEMENT;
INSERT INTO RAP_COUNTRY_ENTITLEMENT VALUES
  ('FR_ANALYST', 'US'),
  ('FR_COMPLIANCE', 'US'),
  ('FR_COMPLIANCE', 'CA'),
  ('FR_COMPLIANCE', 'UK'),
  ('ROLE_ARCH_LAB_ADMIN', 'US'),
  ('ROLE_ARCH_LAB_ADMIN', 'CA'),
  ('ROLE_ARCH_LAB_ADMIN', 'UK'),
  ('FR_DATA_ENGINEER', 'US'),
  ('FR_DATA_ENGINEER', 'CA'),
  ('FR_DATA_ENGINEER', 'UK');

Chunk B — row access policy

SQL · RAP definition
CREATE OR REPLACE ROW ACCESS POLICY RAP_CUSTOMER_COUNTRY
AS (country_code STRING) RETURNS BOOLEAN ->
  EXISTS (
    SELECT 1
    FROM SECURE.RAP_COUNTRY_ENTITLEMENT e
    WHERE e.ROLE_NAME = CURRENT_ROLE()
      AND e.COUNTRY = country_code
  );
4

Attach policies + grant SELECT to access roles

Understand this before you copy

SQLPlain English
MODIFY COLUMN EMAIL SET MASKING POLICYTurn on email masking for that column
ADD ROW ACCESS POLICY … ON (COUNTRY)Filter rows by country entitlement
GRANT SELECT … TO AR_CURATED_READAnalyst path can query the table (policies still apply)
SELECT without policy would leak data. SELECT with policy = least privilege + dynamic obfuscation.
SQL · attach + grants
USE SCHEMA CURATED;

ALTER TABLE CUSTOMERS_GOV MODIFY COLUMN EMAIL SET MASKING POLICY SECURE.MP_EMAIL_MASK;
ALTER TABLE CUSTOMERS_GOV ADD ROW ACCESS POLICY SECURE.RAP_CUSTOMER_COUNTRY ON (COUNTRY);

GRANT SELECT ON TABLE CURATED.CUSTOMERS_GOV TO ROLE AR_CURATED_READ;
GRANT SELECT ON TABLE CURATED.CUSTOMERS_GOV TO ROLE AR_PII_READ;

SELECT 'Lab 03 policies applied on CURATED.CUSTOMERS_GOV' AS status;

Prove FR_ANALYST: masked email + US rows only

Switch role in Snowsight — this is the live demo.

Understand this before you copy

USE ROLE FR_ANALYST activates only the analyst inheritance chain from Lab 01.

  • Email should look like ***@something.com — not the full address
  • COUNTRY should be US only (no CA/UK rows)
  • SSN_LAST4 may still appear — Lab 01 view excluded it; this table includes it for policy contrast (mention column-level security in interview)
If you still see all countries, check the row policy is on COUNTRY and entitlement has FR_ANALYST / US.
Role: FR_ANALYST ▾
SQL · analyst proof
USE ROLE FR_ANALYST;
USE WAREHOUSE WH_ARCH_XS;
USE DATABASE ARCH_INTERVIEW;

SELECT CUSTOMER_ID, EMAIL, COUNTRY
FROM CURATED.CUSTOMERS_GOV
ORDER BY CUSTOMER_ID;
✓ Masked emails · only US in COUNTRY column

Self-check

  1. Why attach policies to CURATED.CUSTOMERS_GOV instead of RAW.CUSTOMERS?
  2. Masking vs row access policy — one sentence each?
  3. What happens if you add a new country row but forget to update RAP_COUNTRY_ENTITLEMENT?
  4. Does masking stop someone with no SELECT privilege?
Click for short answers
  1. Analysts can SELECT curated tables per RBAC; RAW stays blocked.
  2. Masking transforms column values; RAP filters which rows appear.
  3. Rows for that country vanish for all roles until entitlement is updated.
  4. No — RBAC still required; policies apply only after access is granted.
60-second interview answer
“I layer RBAC with dynamic masking and row access policies. Analysts SELECT a curated customer table — email is masked unless compliance or admin, and a row policy filters countries from an entitlement mapping table. I demo the same query as FR_ANALYST vs FR_COMPLIANCE to show column and row differences without duplicating tables.”
