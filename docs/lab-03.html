3

Write the email “frosted glass” rule

Step 3 · coach

What is masking in baby words?

Read the CASE like English

“When the active badge is Compliance or Lab Admin → show the real email. Otherwise → replace everything before @ with ***.”

AS (val STRING) RETURNS STRING = this rule takes one email string in, returns one string out.

SQL · masking policy
USE SCHEMA RISK_CTRL;

CREATE OR REPLACE MASKING POLICY MP_EMAIL_MASK AS (val STRING)
  RETURNS STRING ->
  CASE
    WHEN CURRENT_ROLE() IN ('FR_COMPLIANCE', 'ROLE_BANK_LAB_ADMIN') THEN val
    ELSE REGEXP_REPLACE(val, '.+@', '***@')
  END;
✓ Policy object exists — not yet stuck on the EMAIL column

What is the entitlement list?

Why a table?

Hard-coding countries inside the policy is brittle. A small table is the “who may see which country” checklist. Alex → US only. Sam → US, CA, UK.

5

Write the “hide whole rows” rule

Step 5 · coach

What is RAP?

What RETURNS BOOLEAN means

For each row, Snowflake asks the policy: “May this role see this country?” TRUE = keep the row · FALSE = hide it. EXISTS (…) = “is there a matching line on the entitlement list?”

SQL · row access policy
CREATE OR REPLACE ROW ACCESS POLICY RISK_CTRL.RAP_CLIENT_COUNTRY
AS (country_code STRING) RETURNS BOOLEAN ->
  EXISTS (
    SELECT 1
    FROM RISK_CTRL.RAP_COUNTRY_ENTITLEMENT e
    WHERE e.ROLE_NAME = CURRENT_ROLE()
      AND e.COUNTRY = country_code
  );
6

Hang both rules on CLIENTS_GOV

Step 6 · coach

Why attach both rules?

Attach ≠ create (common gotcha)

CREATE MASKING POLICY only invents the rule. Emails stay plain until you ALTER TABLE … SET MASKING POLICY. If you later CREATE OR REPLACE TABLE CLIENTS_GOV, the stickers fall off — attach again.

SQL · attach policies
ALTER TABLE SILVER_CURATED.CLIENTS_GOV
  MODIFY COLUMN EMAIL
  SET MASKING POLICY RISK_CTRL.MP_EMAIL_MASK;

ALTER TABLE SILVER_CURATED.CLIENTS_GOV
  ADD ROW ACCESS POLICY RISK_CTRL.RAP_CLIENT_COUNTRY ON (COUNTRY);
SQL · prove the sticker is on EMAIL
USE ROLE ROLE_BANK_LAB_ADMIN;
SELECT POLICY_NAME, POLICY_KIND, REF_COLUMN_NAME
FROM TABLE(INFORMATION_SCHEMA.POLICY_REFERENCES(
  REF_ENTITY_NAME => 'MERIDIAN_BANK.SILVER_CURATED.CLIENTS_GOV',
  REF_ENTITY_DOMAIN => 'TABLE'
));
✓ You must see MP_EMAIL_MASK on column EMAIL (and RAP on COUNTRY)

Interviewer presses further — say these out loud

Basics got you into the room. Cover each answer before you open it. If you blank here, an Architect + dbt interviewer will know.

Q1. Why one CLIENTS_GOV with masking + RAP instead of US_CLIENTS and CA_CLIENTS tables?

Say: Shadow copies drift and double the governance surface. Policies centralize rules in RISK_CTRL; Alex and Sam run the same SELECT and CURRENT_ROLE() changes the answer. Physical split only when law demands separate accounts — not laziness.

Q2. RAP filters countries; masking hides email — what breaks if you only do one?

Say: Masking alone still leaks out-of-scope rows’ existence; RAP alone still shows full email for allowed countries. Meridian needs both: entitlement + mask unless FR_COMPLIANCE. Complementary controls, not “we have governance.”

Q3. Can a secure view replace RAP for Alex?

Say: A view can hardcode WHERE country IN (…) but every path must use it and engineers recreate bypass tables. RAP binds to the table so forgetful SELECT * still filters. Views trim columns for shares (Lab 10); RAP is role-driven row entitlement.

Q4. Why not grant APPLY MASKING/ROW ACCESS to FR_DATA_ENGINEER?

Say: Policy apply is a loaded gun; Jordan loading TXN_EVENTS shouldn’t rewire Sam’s rules. Lab admin or a security role applies; FR_COMPLIANCE may own entitlement data. Trial collapses roles — prod separates apply from load.

Q5. Secondary roles NONE again — why do masking demos lie without it?

Say: Policies key off primary CURRENT_ROLE(); table privilege still unions secondaries. You can get “masked but shouldn’t see the table” or unmasked via lab-admin secondary. NONE makes the FR_ badge the only coat in the room.

“Meridian needed one client shelf, not shadow copies. I built SILVER_CURATED.CLIENTS_GOV, stored rules in RISK_CTRL, masked EMAIL unless FR_COMPLIANCE, and filtered rows with a country entitlement list plus a row access policy. Alex and Sam run the same SELECT — masking and RAP change the answer by CURRENT_ROLE(). Outcome: regulators see centralized policy; analysts don’t see full email or out-of-scope countries.”
