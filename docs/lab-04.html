Data Vault — talk-track only (not today’s build)

If Marcus asks “what about Data Vault?”

Data Vault is a modeling style for enterprise warehouses: hubs (business keys), links (relationships), satellites (attributes that change over time). Meridian’s lab stays on a simple three-layer medallion so the story is obvious in one whiteboard.

When Elena mentions it in an interview: “We’d use Vault-style hubs/satellites inside silver if we had many sources and late-arriving keys; for this bank lab, CURATED silver tables plus FINANCE_MART gold keep lineage clear without a fourth naming scheme.”

No Vault DDL in this lab — you’re proving you can name layers and point Alex at the right shelf.

Build silver — clean txns from the dock

What changed from bronze?

  • UPPER(STATUS) — one spelling convention
  • WHERE AMOUNT >= 0 — drop bad rows before analysts aggregate

Matches sql/04_medallion.sql silver definition.

SQL · CURATED.SILVER_TXNS
CREATE OR REPLACE TABLE CURATED.SILVER_TXNS AS
SELECT TXN_ID, CLIENT_ID, UPPER(STATUS) AS STATUS, AMOUNT, UPDATED_AT
FROM LANDING.TXN_EVENTS
WHERE AMOUNT >= 0;
✓ Table under CURATED — row count ≤ LANDING (reversals with negative amount drop if any)
4

Build gold — client-level board metrics

Why aggregate here?

Alex wants lifetime value and txn counts — that’s a business question, not a raw feed. Gold reads silver only, never LANDING directly.

SQL · FINANCE_MART.GOLD_CLIENT_SUMMARY
CREATE OR REPLACE TABLE FINANCE_MART.GOLD_CLIENT_SUMMARY AS
SELECT CLIENT_ID, COUNT(*) AS TXN_COUNT, SUM(AMOUNT) AS LIFETIME_VALUE, MAX(UPDATED_AT) AS LAST_UPDATE
FROM CURATED.SILVER_TXNS
GROUP BY CLIENT_ID;
✓ One row per client_id that appears in silver
5

Prove layer row counts

What you should see

Three layers, three counts — landing ≥ silver ≥ gold row cardinality (gold is grouped by client).

SQL · layer counts
SELECT 'landing' AS layer, COUNT(*) AS n FROM LANDING.TXN_EVENTS
UNION ALL SELECT 'silver', COUNT(*) FROM CURATED.SILVER_TXNS
UNION ALL SELECT 'gold', COUNT(*) FROM FINANCE_MART.GOLD_CLIENT_SUMMARY;
✓ Three rows — Alex should query FINANCE_MART, not LANDING
