Lab 10 · Data exchange · Understand first, then run

Secure data sharing & Marketplace talktrack

Sharing lets a provider expose read-only objects to a consumer account without copying files out of Snowflake. You can complete the provider side in one trial account; cross-account finish needs a second account (optional).

After this lab you can explain
  • Why shares expose secure views — not raw tables with hidden predicates
  • Provider steps: secure view → share → grants → (optional) add consumer account
  • Marketplace vs private share (listing, billing, public discovery)
  • CREATE SHARE privilege — repair script if create fails
Privilege repair If CREATE SHARE fails, run Lab 00 / sql/00_privilege_repair.sql as ACCOUNTADMIN (includes GRANT CREATE SHARE ON ACCOUNT TO ROLE ROLE_ARCH_LAB_ADMIN).

CREATE SHARE privilege (only if Step 2 fails)

Understand this before you copy

Creating shares is account-level. ACCOUNTADMIN delegates it to the lab admin role once.

Same pattern as CREATE ROLE in Lab 01 — architects know which privileges are account-scoped.
SQL · Step 0 · privilege snippet
USE ROLE ACCOUNTADMIN;
GRANT CREATE SHARE ON ACCOUNT TO ROLE ROLE_ARCH_LAB_ADMIN;
1

Secure view — what leaves the building

Only safe columns from RAW.ORDERS_EVENTS.

Understand this before you copy

Why SECURE VIEWPlain English
Predicate / join protectionConsumer cannot inspect view SQL to bypass row filters
Column listYou explicitly export ORDER_ID, totals — not internal PII columns
Interviewers ask: “Why not share the table?” — secure view + least columns is the architect answer.
SQL · Step 1 · secure view
USE ROLE ROLE_ARCH_LAB_ADMIN;
USE WAREHOUSE WH_ARCH_XS;
USE DATABASE ARCH_INTERVIEW;

CREATE OR REPLACE SECURE VIEW CURATED.V_SHARE_ORDERS AS
SELECT ORDER_ID, CUSTOMER_ID, STATUS, ORDER_TOTAL
FROM RAW.ORDERS_EVENTS;
2

Create share & grant objects

Understand this before you copy

GrantWhy order matters
USAGE ON DATABASEShare must see the database container
USAGE ON SCHEMAThen the schema
SELECT ON VIEWOnly the secure view — not whole RAW schema
SQL · Step 2 · share + grants
CREATE SHARE IF NOT EXISTS SHARE_ARCH_ORDERS;
GRANT USAGE ON DATABASE ARCH_INTERVIEW TO SHARE SHARE_ARCH_ORDERS;
GRANT USAGE ON SCHEMA CURATED TO SHARE SHARE_ARCH_ORDERS;
GRANT SELECT ON VIEW CURATED.V_SHARE_ORDERS TO SHARE SHARE_ARCH_ORDERS;
3

Verify provider side

Understand this before you copy

SHOW GRANTS TO SHARE lists exactly what consumers will see after they accept the share.

SQL · Step 3 · inspect share
SHOW SHARES LIKE 'SHARE_ARCH_ORDERS';
SHOW GRANTS TO SHARE SHARE_ARCH_ORDERS;

SELECT 'Lab 10 share created with secure view — add consumer account to complete' AS status;

Cross-account finish (optional — second account)

Skip on a single trial; know the lines for the interview.

Understand this before you copy

Provider ACCOUNTADMIN adds consumer account locator. Consumer creates a database from the share.

Marketplace adds listing, discovery, and commercial terms — same underlying share mechanics with packaging.
SQL · Step 4 · talktrack only
-- Provider (ACCOUNTADMIN):
-- ALTER SHARE SHARE_ARCH_ORDERS ADD ACCOUNTS = <consumer_account_locator>;

-- Consumer:
-- CREATE DATABASE ARCH_ORDERS_SHARED FROM SHARE <provider_account>.SHARE_ARCH_ORDERS;
-- SELECT * FROM ARCH_ORDERS_SHARED.CURATED.V_SHARE_ORDERS LIMIT 10;

Marketplace (no SQL — interview talktrack)

  • Private share — known partner, invite by account locator.
  • Data Exchange — closed group of organizations.
  • Marketplace listing — public/partner catalog, subscription flow, optional monetization.
✓

Quick self-check

  1. Who pays compute when the consumer queries a share?
  2. Why secure view instead of table share?
  3. What privilege does the lab role need to create a share?
Click for short answers
  1. Consumer — their warehouse credits.
  2. Hide definition / enforce column & row logic; reduce over-exposure.
  3. CREATE SHARE ON ACCOUNT (via ACCOUNTADMIN grant).
60-second interview answer
“I expose partner data with a secure view on the minimum columns, attach it to a share with db/schema usage grants, and add consumer accounts explicitly. Consumers query in their account with their compute. For public distribution I’d use Marketplace listings; for one partner, a private share. I never share raw PII tables when a curated secure view suffices.”
